AZHottie Studio v1.60.0 — Creator Club Feed, Discovery & Publishing
Release date: 2026-11-24 (America/Phoenix)

MY CLUBS FEED
Approved, released posts from followed creators and currently accessible tiers
appear together, ordered by actual publication time and stable ID. All updates,
Unread and creator filters apply before pagination; locked or unavailable posts
cannot crowd older eligible updates out of a page.
Mark read and Mark unread are explicit, reversible, account-owned changes.
Loading a feed, opening a post or dismissing an alert does not mark posts read.
A newly approved publication revision becomes unread again. Unread counts
include only currently eligible posts. Following, access and moderation changes
are rechecked on subsequent page and protected media requests.
Continuation cursors are scoped to the account and filters. Follows, notification
preferences and access history remain below the feed. Post read status is
separate from notification read status.

DISCOVERY AND HISTORY
Search the displayed creator name or tagline. A private account name is not
searched behind an active stage name. All creators and Following filters apply
active-model and profile-visibility rules before pagination. Discovery and
individual Club histories continue beyond the previous 80-creator/60-post caps.

PRIVATE DRAFTS AND PREVIEW
Save draft accepts incomplete text, an omitted tier and an unchecked rights
confirmation. Any referenced media or tier must still belong to the creator.
Preview safely renders entered text and uses only authorized personal media;
it performs no save, submission or publication.
Submit for review validates title/content, audience, owned video, the approved
tier when relevant, rights and participant consent. Saving a pending item as a
draft removes it from review. Published or scheduled posts must be withdrawn
before editing and reviewed again. Stale revisions cannot overwrite newer work.

SCHEDULED PUBLICATION
The selected IANA time zone converts a local release time to UTC. Invalid dates,
nonexistent clock times and ambiguous repeated hours are rejected explicitly.
Drafts and pending items never publish merely because a date passes. Future
approved posts wait in Scheduled state. Approval after the requested time
releases the approved version at the actual approval time.
The publisher locks and rechecks the persisted post, revision, active creator,
visible profile, audience, rights, tier and owned media. Attached videos are
pinned to their selected revision; later edits require fresh review before
publication or fan access. Source state, actual
release timestamp, audit and recipient outbox events commit together. Repeated
or overlapping checks cannot release the same version twice. Delivery retries
through the existing shared activity outbox.
Blocked schedules remain private with actionable feedback. Bounded batches
rotate checked blocked rows so newer work is not permanently starved.
Manual and automatic checks have distinct health records. Health uses observed
timestamps, errors and blocked work; manual checks never prove a cron is active.

HOST SCHEDULER SETUP
For this HostGator shared-host deployment, use a 15-minute host cron:

  */15 * * * * /path/to/php-cli /absolute/path/to/azhottie/includes/creator-club-cron.php

Replace both paths with this host's PHP CLI and installed application path.
HostGator's published WordPress cron setup guidance recommends no interval below
15 minutes. This deployment uses that interval. Use a shorter interval only after
the host confirms it is permitted for this account.
Provider reference, checked November 24, 2026 (America/Phoenix):
https://www.hostgator.com/help/article/how-to%20-replace-wordpress-cron-with-a-real-cron-job

Approved posts release on the next successful check after their requested time.
With a healthy 15-minute job and no blockers or backlog, the usual polling delay
is up to 15 minutes. Exact-minute publication is not guaranteed. Failures and
backlog can extend the delay; unapproved content never becomes eligible.

The private expected interval defaults to 15 minutes. To match a different
permitted host cadence, add or update this top-level entry inside the existing
returned array in storage/config.php, preserving all other entries:

  'creator_club' => ['publish_interval_minutes' => 15],

Use an integer from 1 through 60. Invalid settings fall back to 15. This setting
controls health reporting only; it does not create, enable or change a host task.
For a host-confirmed every-minute task, use 1. If relying only on the existing
private hourly agent-followthrough cron, use 60. That fallback also handles due
Club posts, but releases only when its next successful check runs.

Completed automatic runs become stale after two expected intervals plus five
minutes of grace, with a minimum of ten minutes. The default threshold is 35
minutes. A job still running after ten minutes is treated as stale independently
of the expected interval. Manual runs never refresh the automatic heartbeat.
The script is CLI-only; includes/ is denied to web requests. Uploading the ZIP
does not create a host task.
In Commerce → Membership reviews, confirm a recent automatic completed check.
Publish due posts now checks only already approved, due schedules and records
a manual run. Missing/delayed host tasks delay release and never bypass review.
