ACCEPTANCE AREAS (ONE POINT EACH)

1. Install, upgrade and retained data — PASS
   Fresh isolated installations and repeatable migration through schema 16.
   Schema 15 adds saved production plans, original scene/shot links, mutation
   receipts and AI proposals. Schema 16 adds assignment messages and read
   cursors. Existing accounts, roster memberships, assignments, uploads, reviews,
   edits and AI settings are retained. Source storage stays uninstalled and
   untouched. Live MySQL execution remains in area 10.

2. Roles, ownership and private script context — PASS
   The current production owner administrator controls the full plan and
   casting. Other administrators, fans and unassigned members cannot access
   private plans or assignment threads. An authorized contributor receives the
   original scene/shot context relevant to their work, without the full plan,
   roster identities or other private assignments. Current account, role,
   password and production permissions are rechecked on sensitive requests.

3. Saved direction, scenes and linked work — PASS
   Manual planning works without an AI key. Plans keep independent revisions
   and ordered scene/shot IDs. Validation covers text lengths, orientation,
   deadlines, takes, capacity and the 20-scene/60-shot/12-shot-per-scene limits.
   Applying a scene preserves its original script and created-shot link. The
   planner makes applied scenes read-only; current shot instructions can be
   changed through the existing workspace without replacing assignments or
   footage. Linked progress comes from actual work state.

4. Casting and atomic assignment creation — PASS
   Leave unassigned, open to included models, and direct casting use existing
   eligibility, roster, capacity and project rules. Plan and roster revisions
   must match at application. Failed or stale batches leave no partial shots,
   assignments, notifications, scene links or successful receipts. A deliberate
   mid-transaction database fault and simultaneous apply requests are covered.
   The producer retains the existing studio self-contribution exception.

5. AI proposals and reviewed adoption — PASS WITH PROVIDER FIXTURES
   Production plans reuse the Admin Shot-list assistant provider/model. Plan,
   quick-shot and edit proposals share the request allowance and pending limit.
   Capacity is checked before reserving quota or calling a provider. Structured
   output, response size, scene/shot budgets, timeout, current authorization and
   stale project/plan/actual-shot sources are validated. Outbound drafts contain
   approved creative text and titles; identities, private profiles, messages,
   media and reference-file bytes stay local. Adopting a reviewed proposal
   appends draft scenes; creating assignments remains a separate action.
   No actual external OpenAI or Claude request was made.

6. Private questions, retries and unread state — PASS
   Each assignment has a producer/assignee-only, append-only text conversation.
   Exact resend receipts prevent duplicate messages and in-app notifications.
   An altered payload cannot reuse a successful request ID. Reads acknowledge
   an existing sequence monotonically and exclude the reader's own messages.
   Messages and read cursors do not change work/project revisions. Closed
   assignments/projects keep authorized history while disabling new posts.
   Roster removal preserves an existing explicit assignment and its thread.

7. Controller integration and recovery — PASS WITH TEST DOM/MEDIA
   Initial loading, failed-load recovery, reviewed application, draft recovery,
   casting changes, read-only receipt recovery, CSRF renewal and parent busy
   guards are covered. In-place shot refresh preserves other mounted drafts.
   Interrupted message sends retain the original request and text separately
   from new typing. Read acknowledgements use the highest rendered sequence;
   a late read response cannot overwrite newer unread state. A refresh that
   completes in a hidden tab does not acknowledge unseen replies. Responsive
   CSS is implemented; visual appearance remains part of area 10.

8. Connected production workflow — PASS WITH SYNTHETIC MEDIA
   A full HTTP scenario saves a two-scene plan, creates direct/open work,
   verifies private script access, exchanges questions and replies, activates
   the production, claims/accepts work, uploads/submits a take, requests and
   approves a replacement, removes a roster member without losing work, then
   verifies accepted sources in the editor and exact finished-video provenance.
   Synthetic media fixtures do not establish real browser export/codec quality.

9. Existing studio behavior — PASS WITH TEST FIXTURES
   Interview recording state, phone approval/upload, account roles, scheduling,
   events/classes/appointments, capacity/attendance, roster controls, media
   access, Director coverage, usable ranges, named cuts, editing proposals,
   covers, finished-video metadata and explicit publication regressions pass.
   Central AI encryption, migration and routing tests remain green. Source
   files remained unchanged during the final automated runs.

10. Installed host, browser, providers and physical devices — UNVERIFIED
    Actual HostGator/other host, live MySQL, browser appearance, USB/HDMI/phone
    cameras, external audio, Safari/iOS, real codecs, phone-network WebRTC and
    configured-provider requests remain installation checks. No credentials,
    host access or physical-device access were assumed. This area earns no
    verified point until the installed acceptance checks succeed.

V1.7 REVIEW CORRECTIONS

- Moving a planned shot from direct casting to open/unassigned clears old
  selected account IDs. The scene editor enforces the 12-shot-per-scene limit.
- Initial plan-load errors display a recoverable error and Reload control.
  Read-only bootstrap can initialize inside the parent production-save guard.
- CSRF renewal fetches a fresh token without replacing the user's draft,
  proposal review, or interrupted request identity, then retries once.
- Delayed read acknowledgements cannot overwrite later unread counts. Reply
  refreshes completing while the tab is hidden leave unseen messages unread.
- Previously sent message/generation receipts remain recoverable after a
  production closes; new writes/generation stay disabled.
- AI generation preflight accounts for remaining plan capacity and the actual
  production shot ceiling, including uncreated shots already in the plan.
- The member script panel is labeled Original plan script and indicates when
  the created shot has changed. Current shot directions remain authoritative.
- Plan and quick-assistant application refresh the existing workspace in place
  so other drafts, mounted conversations and capture guards are preserved.

SHORT INSTALLED ACCEPTANCE SEQUENCE

1. Back up the existing application and complete storage/database. Merge this
   release into the same directory without reinstalling or deleting storage.
   Sign in and hard-refresh. Confirm the automatic upgrade reaches schema 16.
2. Open Productions, create/open a draft production and include two approved
   models; leave a third eligible account outside the roster. Open Production
   plan, save direction, add two scenes and save the plan. Reload and confirm
   the saved script and casting are retained.
3. Make one shot open to included models and one direct to a single model.
   Review shots and assignments, then create the batch. Repeat/reload the
   result and confirm no duplicate work. Activate the production. Included
   members should discover eligible open work; only the assignee should see
   the private direct shot. The outside account should see neither.
4. As the assignee, open the original scene script, send a question, refresh
   replies and acknowledge the conversation. As producer, answer it and check
   unread indicators. Confirm another model cannot read this conversation.
5. Claim/accept work, record/upload, submit, request a retake and approve the
   replacement. Remove a roster member and confirm existing work, script,
   footage and questions remain authorized while new open work disappears.
6. Open approved footage in the editor, save a named cut, export and Save
   finished video. Add a cover and inspect exact source/revision provenance.
   Check phone uploads, optional phone live switching, local external inputs
   and the selected microphone on the intended browsers/devices/network.
7. If using AI, confirm the saved Admin provider/model and run one bounded
   real draft with each configured provider. Review/adopt it, cast locally,
   then separately review/create the assignments. Check actual response,
   timeout and provider billing behavior in that installed environment.
8. If public release is intended, explicitly publish a finished cut to Watch
   and inspect it as a fan/signed-out visitor. Original footage and private
   production scripts/questions remain subject to studio permissions.
